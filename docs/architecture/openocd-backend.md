# Opt-in CMSIS-DAP/OpenOCD backend

`tools/nrfkit openocd` reuses the existing image manifest loader, ELF/HEX address
checks, immutable programming snapshots, probe locks, process timeouts and run
reports. The normal nrfutil/J-Link commands remain the reference backend. An image
manifest's existing nrfutil contract is preserved; selecting this separate CLI
explicitly chooses the evaluated OpenOCD transport and records its executable and
Tcl hashes in the run report.

Supply an external OpenOCD build with the `nrf54lm20` application-RRAM driver and
matching `target/nordic/nrf54lm20.cfg` scripts. The SDK neither builds a fork nor
adds it to the consumer dependency graph. Local paths belong only in the inventory.
The evaluated external baseline is OpenOCD
`046c040cb0012e2f908bb11009b39bf502cff6f3` with an application-RRAM patch.
This is not a claim of upstream OpenOCD flash support.

The adapter setup is generated by the repository. It selects exactly one discovered
CMSIS-DAP USB bulk interface and serial, binds GDB to loopback only when required,
and disables Tcl/Telnet services. nRESET must be wired: resets use physical SRST,
not CTRL-AP soft reset. Supported SWD requests are 1000, 2000 and 4000 kHz, with the
conservative request as default; these are requests, not measured SWCLK frequencies.

Before commands act on the target, FICR PART must identify LM20A or LM20B and report
2036 KiB RRAM. PART, VARIANT and device ID offsets come from the locked A/B Datasheet
v1.0 §4.2.4.1. Receipts retain the actual identity. The DK's LM20B validates shared
LM20 functionality; NPU support is outside scope.

- `list` enumerates the adapter without connecting to the target.
- `info` reads target identity; it can enter debug-interface mode.
- `flash --manifest` programs guarded addressed HEX snapshots without erase and
  verifies them. The CPU remains halted. No arbitrary BIN address is accepted.
- `backup --manifest` accepts repeated manifests and saves the union of bytes those
  images can overwrite, rounded to 16-byte RRAM units within each allowlist. Two
  independent reads must match before addressed HEX backups are published.
- `restore --manifest --backup-report` requires a successful backup, unchanged
  artifact hashes, matching target identity, and ranges within the supplied
  manifest's allowlist. It verifies restored bytes and leaves the CPU halted.
- `backup` and `restore` accept `--include-settings` to preserve the separate,
  16-byte-aligned ordinary RRAM settings span declared by the audited ELF. The
  default remains image bytes only; protected regions are never included.
- `reset` requests a pin reset and resumes execution.
- `gdb-smoke --manifest --gdb` exercises main and single-step with hardware
  breakpoints. `--runtime-contract` adds the hardware-validation firmware's RAM,
  post-main, reset-vector and watchpoint checks. `--attach --observe SYMBOL` inspects
  an existing image without reset, then resumes and detaches. It does not prove
  that the supplied ELF matches running firmware; establish that separately.

Ordinary snapshots and backups are not authorization to touch configuration,
protection, factory or one-time regions. Restoring application bytes does not restore
volatile peripheral state; choose an explicit reset/cold-start phase afterward.
GDB failure leaves target state unclaimed, with server cleanup recorded. Software
flash breakpoints, power-loss programming recovery and full M2/M7 acceptance are
separate evidence, not inferred from a successful attach.

Host tests cover argument quoting, identity/range rejection, rounded backup bounds,
and stale or wrong-target restoration. Live USB enumeration has passed. Guarded programming/readback, double-read backup/restore, and post-cold-start
GDB attach/read have passed on LM20B. Physical reset did not restart the tested
fixture, so reset-dependent main/step/watchpoint gates remain pending. See the
[measurement results](../validation/power-measurement-2026-09-11.md).

If running firmware locks application writes until reset, a restore can fail
without an image-guard failure. Where a separately backed-up writable boot region
is available, program the quiet probe there, cold-start it, restore application
and settings, then restore the original boot region while halted. Do not modify
protection settings or infer that an ineffective pin reset cleared runtime locks.
